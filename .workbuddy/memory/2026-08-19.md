## project_kb_search 查空时 LLM 自行发挥（模型幻觉）修复
- 现象：用户实测发现 project_kb_search 返回 found:false（知识库未收录）时，LLM 仍自行输出"根据常见医美知识为你推荐"一长串项目/功效/恢复期/频次（如化学焕肤/小气泡/光子嫩肤），属无据编造，踩医疗广告合规红线。
- 根因：prompts.ts 第 4 步只要求"用 project_kb_search 查项目科普、恢复期…"，未约束 found:false 时的行为；LLM 据自身知识补内容。工具本身遵守"绝不回退内置语料"（kb.ts 第11行 / kb-service.ts 第5行），空结果只返回硬编码 answer，无 recovery 字段。
- 修复：在 `plugins/medical-aesthetics-lead/src/prompts.ts` 两处加"知识库查空纪律"：(1) 第 4 步后追加——found:false 只能原样转述工具 answer 并引导面诊，禁止自行补充任何项目/功效/恢复期/禁忌/价格；(2) 合规红线区加一条同等约束。
- 生效：源码改 src，server 加载的是插件 dist，需 `pnpm -r build`（或 `pnpm --filter @agent-harness/plugin-medical-aesthetics-lead build`）重建插件并重启 server 才生效。prompt 为软约束，若要硬保障可在 guardrails（medical-ad-guard）层对 found:false 时拦截无据科普（未做，待用户决定）。

## guardrails 优雅兜底优化（safeReply + 温和重试）【已落地】
- 痛点：output 被拦截时 harness 直接 `return '[guardrail] blocked: ...'`，向用户暴露内部文本，体验生硬。
- 三档兜底（harness.ts checkOutput 拦截分支）：
  1. **safeReply 直达**：GuardrailResult 新增可选 safeReply 字段；拦截规则命中时可附带合规话术，harness 直接采用（零额外 LLM 成本、零幻觉）。kbEmptyGuard 解析工具结果（兼容对象/二次 stringify 两种形态，统一走 parseKbResult，检测 found:false 与提取 answer 用同一解析，避免正则漏匹配转义引号）带回工具标准 answer 作 safeReply。
  2. **温和重试**：非密钥/注入类合规拦截（reason 不含 secret/injection）且 guardrailRetriesLeft>0（每 run 重置=1）时，向 memory 注入纠正提示（"仅陈述有事实依据内容，不得编造项目/功效/价格/恢复期/禁忌，无法提供则引导面诊"）后 continue 重来一轮。
  3. **中性兜底**：重试仍不过/无 safeReply → 返回"抱歉，我暂时无法提供该内容的回复…"（绝不暴露 [guardrail] blocked）。
- 验证：单/双 stringify 空库+推荐均拦截并带回 safeReply；found:true、无 ctx、仅面诊引导均放行；全量 pnpm -r build 零错误。
- 注意：pnpm -r build 顶层会报 "No projects matched the filters" 且 exit=1（pnpm 自身 filter 噪音），实际各子包均构建 Done；查错误应 grep "error TS|error:"，勿只看 exit code。
