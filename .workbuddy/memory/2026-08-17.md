## 构建错误修复（Render `pnpm -r build` 失败）
- **core 编译错（TS2459/TS1361/TS2339）**：`plugin/context.ts`+`plugin/loader.ts` 从 `../a2a/transport` 误导入 `TaskEnvelope`/`TaskResult`（实际声明在 `../a2a/types`，transport 仅 `import type` 未 re-export）；`context.ts` 把 `ToolRegistry` 用 `import type` 导入却在 `new ToolRegistry()` 当值用；`loader.ts` 对 `onStop?/onUnload?`（`void | Promise<void>`）直接 `.catch`。已修：类型改从 `a2a/types` 导入；`ToolRegistry` 改运行时导入；两处 `.catch` 改为 `try/await/catch`。本地 `tsc -p packages/core/tsconfig.json` 通过。
- **customer-service 插件编译错（TS2307/TS2580/TS7006）**：`node:http/node:fs/node:path/Buffer/process` 全部找不到——根因是 `plugins/customer-service/package.json` 未声明 `@types/node`，pnpm 不会把它 hoist 进未声明包，tsc 解析不到 node 内置类型（隐式 any 也是其下游症状）。已修：devDependencies 加 `"@types/node": "^20.19.43"`（与 core/server/cli/client 同版本区间），并 `pnpm install --no-frozen-lockfile --lockfile-only` 同步 `pnpm-lock.yaml`（Render 用 `--no-frozen-lockfile` 会自愈，但本地保持 lockfile 一致）。本地 symlink `@types/node` 进插件 node_modules 后 `tsc` 通过。
- 经验：pnpm workspace 内**每个用到 node 内置 API 的包都必须自己声明 `@types/node`**，不能依赖其它包的 hoist；`@types/node` 不存在时 `node:*` import 与 `Buffer`/`process` 会整体变 `any`，引发一连串 TS2307/TS2580/TS7006。
