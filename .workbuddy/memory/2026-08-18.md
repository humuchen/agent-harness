# 2026-08-18

## 修复角色/权限列表（RBAC 矩阵）展示不全

**根因**：webapp `packages/webapp/src/observability.ts` 的 RBAC 矩阵渲染，列（角色）来源是接口返回的 `roles` 字段，而动作行来自 `permissions` 的权限并集——两处并行来源。一旦 `roles` 在接口返回中被截断/缺失（典型：**开放/未启用 RBAC 模式** `describe()` 返回 `roles:[]`+`permissions:{}`），整张表的角色列会静默消失，等价于「数据展示不全」。服务端 `RoleBasedAuthorizer.describe()` 又把 `roles` 硬编码为 `['admin','operator','viewer']`，与 `permissions` 维矩阵分两处维护，存在不同步隐患。

**修复（双层）**：
1. `packages/server/src/authz.ts`：`describe()` 改为 `roles = Object.keys(this.matrix)`——以权限矩阵（数据权威来源）的键派生角色列表，保证接口返回的 `roles` 与 `permissions` 永远一致、完整，从源头消除不同步。
2. `packages/webapp/src/observability.ts`：
   - 新增 `roleColumns()`：优先用 `roles`，当其为空/缺失时**回退从 `permissions` 键推导**，凡有权限数据的角色都不会被漏列。
   - `matrixRows()` 对 `permissions[role]` 做 `Array.isArray` 守卫，容忍字段缺失/非数组（不再抛错）。
   - 渲染头部/单元格统一用 `roleColumns()`；空状态 `colspan` 动态化；开放模式给出准确提示「鉴权未启用（开放模式）：所有请求默认拥有完整权限（等效 admin）」。

**验证**：
- core/server/webapp(observability.ts) 均 `tsc` 通过；server 重建后 `/api/roles` 两种模式均自洽。
- 用 4 组场景（正常 / roles 缺失回退 / 非数组防护 / 开放模式）跑通渲染逻辑断言，全部 PASS。
- 注意：webapp 整体 `tsc --noEmit` 仍因 `chat.ts` 三处**预存**类型错误（agentId / tokencache TraceKind，与本次无关、不在我的 diff 内）无法走 `vite build`；observability.ts 本身零错误。chat.ts 属独立漂移，未擅自扩范围修复。
