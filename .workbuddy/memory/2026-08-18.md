## cost 记账修复（调用链路中成本显示为 $0.0000）

- 现象：UI 调用链路「成本 / 用量」行显示 `cost $0.0000`，但 tokens 不为 0。
- 根因：
  1. `packages/core/src/llm/pricing.ts` 价目表未登记当前默认模型 `agnes-2.5-flash`，`estimateCost` 对其按默认价 0 估算，导致 `run:cost` 事件的 `cumulativeCost/stepCost` 恒为 0。
  2. 旧逻辑无法区分「模型免费」与「模型未定价」，UI 上 `$0.0000` 看起来像 bug。
  3. 余额/扣减：当前系统仅做成本累计与预算熔断，无账户余额扣减逻辑，因此不涉及扣减修复。
- 修复：
  - `pricing.ts`：
    - 增加 `'agnes-2.5-flash': { prompt: 0, completion: 0 }`（该模型官方当前免费）。
    - 新增 `estimateCostDetailed(model, usage)`，返回 `{ cost, found, promptPrice, completionPrice }`；`estimateCost` 保持向后兼容。
  - `harness.ts`：改用 `estimateCostDetailed`；`run:cost` 事件新增 `priced?: boolean`；未命中定价且 cost 为 0 时 `structLog('warn', ...)` 提示排查。
  - `server/src/server.ts`：`run:cost` 转发时把 `priced` 以字符串 `'true'/'false'` 写入 trace meta。
  - `webapp/src/chat.ts`：`buildInsights` 提取 `costPriced`；`renderInsights` 中当 cost 为 `$0.0000` 时，根据 `priced` 显示「免费」（命中定价，如 agnes）或「未定价」（未命中定价表）。
- 验证：
  - `pnpm --filter @agent-harness/core build` 通过；`node --test test/cost.test.cjs test/telemetry.test.cjs test/quota.test.cjs` 25 用例全过。
  - `pnpm --filter @agent-harness/server build` 与 `pnpm --filter @agent-harness/webapp build` 均通过。
  - 端到端脚本验证：`run:cost` 事件对 `agnes-2.5-flash` 返回 `"priced":true, "cumulativeCost":0`；设置 `LLM_DEFAULT_PRICE_PROMPT_PER_M=1 LLM_DEFAULT_PRICE_COMPLETION_PER_M=2` 后未知模型正确估算为 $3。
  - 产物扫描确认 `agnes-2.5-flash` 价格条目、`priced` 字段、「免费/未定价」文案均已进 dist。

## Token 缓存命中率指标统计（新增功能）

- 背景：代码库原本**没有 token 缓存统计模块**；`shared.ts` 对 LLM 请求打 `cache_control`（PROMPT_CACHE=true 时），但供应商返回的 `prompt_tokens_details.cached_tokens` 被 usage 归一化时丢弃。
- 新增 `packages/core/src/llm/token-cache-metrics.ts`（自包含，不 import telemetry 以避免循环依赖；日志/告警经可注入 sink 上抛）：
  - 实时计数器 O(1) 递增（无锁、无异步、热路径零分配）；`recordTokenCacheQuery({hit,cachedTokens,promptTokens,model})`。
  - `getTokenCacheStats()` 快照：queries/hits/hitRate（命中次数/总查询次数）、cachedTokens/promptTokens/tokenHitRate（token 级）、`byModel` 维度。
  - `startTokenCacheAggregation({intervalMs,threshold,minSamples})`：独立 `setInterval` + `unref()`（不阻塞主流程/进程退出）；每个窗口算增量、输出 `token-cache window` 结构化日志；窗口命中率 `< threshold` 且样本 `>= minSamples` 时经 alert sink 发 `token-cache-hitrate-low` 告警。
  - `getTokenCacheHistory()`（最近 120 窗口）、`stopTokenCacheAggregation()`、`setTokenCacheLogger/AlertSink`。
  - 默认阈值/间隔经 env：`TOKEN_CACHE_AGGREGATE_INTERVAL_MS`(60000)、`TOKEN_CACHE_HITRATE_ALERT_THRESHOLD`(0.2)、`TOKEN_CACHE_ALERT_MIN_SAMPLES`(10)。
- 埋点：`shared.ts` 的 `callOpenAIChat` 与 `streamOpenAIChat` 均提取 `prompt_tokens_details.cached_tokens`（兼容 `cached_prompt_tokens`），累计进 usageAcc，并在 `PROMPT_CACHE` 开启时 `recordTokenCacheQuery`；流式路径同步补 `cache_control`。`TokenUsage` 增加可选 `cached_tokens`。
- 查询接口/日志：`server.ts` 在 `setupAlerting()` 中 `setTokenCacheAlertSink(emitAlert)+startTokenCacheAggregation()`；`/api/metrics` 合并 `tokenCache` 与 `tokenCacheHistory`（GET，受令牌保护）。
- 性能：record 仅整数递增；聚合在后台定时器，对主流程无显著影响。
- 验证：core+server build 通过；`token-cache.test.cjs`(2) + `token-cache-agg.test.cjs`(4) 共 6 用例全过（聚合测试独立进程避免模块级状态污染）；全量 core 272 用例 269 通过/3 失败（3 个为 docker/k8s/native 环境缺失，预存）；端到端 mock fetch 调 `callOpenAIChat`（PROMPT_CACHE=true）确认 1 查询/1 命中/缓存 820 token 正确入账；dist/server.js 已含 tokenCache 合并。
