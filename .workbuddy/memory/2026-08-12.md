## UI 测试诊断：闭环提前结束 + token 消耗大（用户反馈，根因定位）
- **现象1 复杂任务闭环直接结束**：根因两条。
  - 出口A：`maxSteps` 默认 **12**（`packages/core/src/harness.ts:76`），且 `runner.ts assembleAgent` 未透传 `maxSteps`（UI 也无入口）→ 复杂任务 >12 步时返回 `'[agent] reached max steps without a final answer'`（`harness.ts:286`），用户误以为完成。
  - 出口B：唯一终止条件是「LLM 不再返回 tool_calls 即 `return resp.content`」（`harness.ts:239`）；模型一旦返回文本/反问/空响应（含 `shared.ts` 退化响应重试后仍空）即结束，**无完成校验/自我修复**。弱模型复杂任务常触发。
- **现象2 token 消耗大**：结构性，非偶发。
  - 每步 `memory.history()` **全量重发**（`harness.ts:179`）→ 累计 prompt tokens ≈ O(步数²)；工具原文（web_fetch/文件/MCP 输出）逐字存 `tool` 消息（`harness.ts:278`）并被后续每步重发，无截断/摘要。
  - 系统提示词（base + 全量 `skillCatalog` + `skillBoost`，`runner.ts:224`）每步重发，无 prompt caching（`cache_control`）。
  - **跨 run 放大**：若 `MEMORY_BACKEND=sqlite/file`（持久化开启），`harness.ts:132` `memory.load()` 把该会话之前所有 run 的历史+工具输出全部载入并随新 run 重发 → 多轮对话 token 乘倍。默认 volatile 则每 run 独立、不跨 run 累积。
  - `maxWindow=20`（`memory.ts:32`）滑动窗口阀值高，复杂 12 步 run 才可能在末尾截断，且截断会丢最早的 user 请求/系统提示（系统提示被丢后 `harness.ts:147` 守卫会再次注入 → 重复）。
  - `callOpenAIChat` 默认重试 2 次（`shared.ts:67`）+ 退化响应重试，每次重试重发全量 prompt，免费/弱模型抖动时进一步放大成本。
- **建议（待用户确认是否动手）**：① `maxSteps` 提到 20~30 或 UI 可配；② 加完成自检（模型声明 done 前校验）；③ 工具输出截断/摘要；④ 上下文压缩（early turns 摘要）+ 真正按 `maxWindow` 裁剪；⑤ prompt caching；⑥ 持久化开启时按 run 分段、不直接整体重发历史；⑦ 重试与退化响应计入 token 预算。

## 构建踩坑：core dist 缺失导致 ui/examples 报「幽灵类型错」
- **现象**：`pnpm -r build` 中 `packages/ui` 报 `mcp-manager.ts(72): reconnecting 不存在于 McpServerMeta`、`server.ts(782): 'fatal' 不可赋给 LogLevel`——但当前源码 `mcp-manager.ts` 已用 `reconnectAttempts`、`telemetry.ts` 的 `LogLevel` 已含 `'fatal'`，源码根本无该字面量。
- **根因**：UI/examples 通过 `paths` 把 `@agent-harness/core` 指向 `packages/core/dist/index.d.ts`（见 MEMORY 工程现状）。本工作区 `packages/core/dist/` **整个不存在/陈旧**，UI 类型检查拿到的是旧 dist；core 上次编译因 `status/health` 等 16 处错中断，dist 从未生成，于是 UI 用到缺 `fatal`/`reconnectAttempts` 的旧类型。
- **结论/复用规则**：遇「UI/examples 报的类型错误在当前源码里找不到」时，先 `cd packages/core && rm -rf dist && tsc -p tsconfig.json` 重建 core dist，再建 UI/examples。切记 `tsc` 每条命令须带绝对 `cd`（沙箱 shell 不跨调用保留 cwd）。`pnpm -r build` 拓扑序本应先 core 后 ui，但若 core 构建失败则 ui 会吃陈旧 dist。
