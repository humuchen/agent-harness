## P1-8 架构解耦（任务队列 / Worker + MCP 单例竞态）—— 已完成并 commit
- **运行队列**（新增 `packages/ui/src/run-queue.ts`，`RunQueue` 单例 `runQueue`）：把「一次 run」抽象为 Job，提交与执行解耦。`submit({mode,prompt,model})` 立即返回 jobId（SSE 只收事件流），worker 池按并发上限 `RUN_CONCURRENCY`(default 4) 异步执行；超并发排队，空闲自动续跑。`subscribe(id, fn)` 先重放事件缓冲（上限 `RUN_QUEUE_BUFFER` default 500，防内存泄漏）再转发后续；Job 结束含终结事件 `_done`，订阅方据此关连接。`stats()`/`list()` 供 `/api/jobs` 与 `/api/metrics`。
- **server.ts 重写 `handleRun`**：先 `readBody` 再 `startSse`（修体超限先 200 再报错）；支持 `body.jobId` 断线重连（直接 `subscribe` 已有 job 重放流、不重复执行）；提交时发 `job:accepted` 带 jobId。`/api/jobs` 入 `PROTECTED` 并加 GET 端点；`/api/metrics` 合并 `queue: runQueue.stats()`。移除 `HarnessEvent` 内联 import（下沉到 run-queue.ts）。
- **mcp-manager.ts 串行化锁**：`withLock` 把 init/addServer/reconnect/connectPreset/shutdown 全部排入同一条 promise 链，消除并发 push / 重复注册竞态；读操作（list/liveRegistry/presets）返回副本安全并发。`connectPreset` 在锁内复用 `addServerUnguarded` 避免嵌套锁。
- **前端 `index.html`**：`state.jobId` 初值 null；`dispatchHarness` 处理 `job:accepted`(存 jobId) 与 `_done`(清 jobId/running)；`realStream()` 加「最多 2 次」断线自动重连（携带 `jobId` 续订事件流，防重连风暴）。
- **配置/文档**：`.env.example` 加 `RUN_CONCURRENCY`/`RUN_QUEUE_BUFFER` 段；README 加「运行队列与水平扩展」小节；测试计数正文订正为 92 用例。

## P1-9 会话/多租户记忆存储（DB 化）—— 已完成待 commit
- **可插拔存储后端**（新增 `packages/core/src/memory-store.ts` + index 导出）：定义 `MemoryStore` 接口（`kind`/`load`/`save`/`delete`/`list`）+ `PersistedMemory{window,longTerm}`；三种零 npm 依赖实现：
  - `VolatileMemoryStore`（默认，纯内存，`hasPersistence=false`）
  - `FileMemoryStore`（按 key 分桶的 `<dir>/<key>.json`；旧单文件 `persistencePath` 模式向后兼容，仅 key=''）
  - `SqliteMemoryStore`（Node 22+ 内置 `node:sqlite`，零依赖、无需启动 flag）。**关键技巧**：用 `import('node:sqlite' as any)` 动态加载 + `as any`，既能在 @types/node 20 工具链编译通过，又能在 Node 22 运行期加载；老 Node 构造/初始化抛错由调用方回退 file。
- **`memory.ts` 改造**：`MemoryOptions` 加 `store?`/`sessionKey?`，保留 `persistencePath`；`hasPersistence` 改为 `store.kind !== 'volatile'`；`load/save/clear` 按 `sessionKey` 调 store；新增 `backend`/`key` getter。`assembleAgent` 现按 store + sessionKey 隔离记忆。
- **UI 多租户接线**（server.ts + run-queue.ts + runner.ts）：
  - `runner.ts` 加 `getMemoryStore()` 单例（按 `MEMORY_BACKEND`=sqlite/file/volatile 选后端并缓存；sqlite 失败回退 file 并告警）；`assembleAgent` 末位加 `sessionKey?`。
  - `run-queue.ts`：`RunJob` 增 `sessionKey`，`submit` 接收，`execute` 透传给 `assembleAgent`。
  - `server.ts` `handleRun`：从 `body.sessionId`/`x-session-id` 头派生 `sessionKey`（`sanitizeKey` 防穿越，默认 `anonymous`）传入 submit；新增受保护端点 `GET /api/sessions`（列 key+后端）、`GET|DELETE /api/memory?session=<key>`（查看/清空某会话）、`/api/metrics` 加 `memory.backend`。
- **测试**：新增 `packages/core/test/memory.test.cjs`（8 用例：sanitizeKey / Volatile / File 分桶隔离 / File 旧单文件 / Memory+后端 / 不同 key 隔离 / 默认 volatile / Sqlite 运行期可用时 round-trip，不可用则跳过）。core 测试 92→100 用例；README 计数订正为 100 + 加「会话/多租户记忆存储」小节；`.env.example` 加 `MEMORY_BACKEND`/`MEMORY_DIR`/`MEMORY_SQLITE_FILE` 段。
- 验证现状：沙箱仍无法本地编译/跑测试，改动人工复核（括号/签名/导入/竞态/scope）；编译风险点已用 `as any` 规避 node:sqlite 类型缺失；CI 将 build→test（core 100 + ui 集成）+ 安全作业。
