## chat.ts 新增「回到底部」浮动按钮
- 需求：消息超视区且用户上滚看历史时，在输入框与内容区之间显示向下箭头按钮；点击平滑滚回底部并自动消失；不遮挡输入/内容。
- 实现（frontend/webapp/src/chat.ts）：
  - 新增 `@state stickToBottom`（默认 true）与 `@state showScrollDown`（默认 false）。
  - `.scroll` 外层包 `.scroll-region`（position:relative，作为按钮定位上下文），按钮 absolute 钉在消息区底部中央，不进入文档流、不挤占输入框。
  - `onScroll()`：距底 ≤24px 判 atBottom，置 stickToBottom=atBottom、showScrollDown=!atBottom，驱动按钮显隐。
  - `scrollToBottom()` 改为仅在 stickToBottom 时跟随——用户上滚看历史不再被新 token 抢滚（保留原钉底体验）。
  - `scrollToBottomSmooth()`：点击按钮 `el.scrollTo({behavior:'smooth'})` 并置 stickToBottom=true，滚到底后 onScroll 自动隐藏按钮。
  - `send()` / `selectSession()` / `newChat()` 重置 stickToBottom=true（发消息/切会话/新对话回到最新底部）。
  - 类型检查通过（webapp `tsc -p tsconfig.json`，chat.ts 无错误；app.ts/dashboard.ts 的 `ServerState.sandbox` 报错为既有依赖类型不一致，与本次改动无关）。
- 附：顺手将超 12KB 的 MEMORY.md 精简到 ~1.6KB（满足 3000 字符上限）。

## 联网搜索改为「显式开启才调用」（Request 4）
- 根因：UI 开关 `this.web`（@state web=false 默认关）从未透传到后端；`registerBuiltinTools` 中 `webEnabled` 默认 true，导致 `builtin__web_fetch` 与 `web-research` 技能始终注册，用户一问外部/最新信息就触发出网检索。
- 修复（请求仅在显式开启时才联网）：
  - 调用链全链路贯通：chat.ts `send()` `web: this.web || undefined` → server.ts `web: typeof body.web==='boolean'?body.web:undefined` → run-queue `submit`/`makeJob`/`RunJob`/`JobDescriptor`/`replayPending` 全加 `web?: boolean` → `assembleAgent(job.web ?? false)`。
  - `assembleAgent` 新增末位形参 `webEnabled?: boolean`（默认 true 向后兼容）；`builtinWebEnabled = (BUILTINS_WEB!=='false') && (webEnabled ?? true)` 双闸门；`registerBuiltinTools` 用 `builtinWebEnabled`；`web-research` 技能在 `!builtinWebEnabled` 时从 `registerMany` 过滤剔除（同时其不再进入系统提示词/触发词预激活，`builtin__use_skill` 取回“未找到”）。
  - 注意：run-queue 调用 assembleAgent 原以 `sandboxBackend` 收尾，新增 webEnabled 后必须显式补一个 `undefined` 占住 `streamTokens` 形参位，否则 `job.web` 会被错赋给 streamTokens（已修）。
  - 直接调 assembleAgent 的 workflow-executor/agent-run/examples 不传 webEnabled → 默认 true，行为不变（最小爆炸半径，仅聊天 UI 路径受开关约束）。
- 验证：core / client / server / webapp 四包 tsc 全过（含 client dist 重建后 webapp 旧 sandbox 报错一并消除）。

## 聊天历史容错持久化（本地镜像层）
- 根因：selectSession 的 `catch { this.threads[id]=[] }` 在恢复失败时清空覆盖本地缓冲，且空数组被当作「已加载」永久缓存不再重试；前端消息仅内存+服务端两份，无本地镜像。
- 新增 `frontend/webapp/src/chat-history.ts`：localStorage 镜像层（key `ah_chat_history_<sid>` + 索引 `ah_chat_index_v1`）：
  - `sanitizeMessages()`：类型收敛/非法条目过滤/连续重复去重/保序/超长截断；
  - `mergeThreadHistories()`：server 尾 × local 头最长 (role+content) 重叠合并，防丢消息与重复；
  - `saveThread()/loadThread()/purgeSessionMirror()/loadIndex()/withTimeout()`；
  - 写入降级阶梯：完整→去 trace→裁半×2，配额不足静默降级不抛错。
- chat.ts 接入：
  - 写入点：send() 用户消息入缓冲后 + run 收尾 finally 各镜像落盘一次（独立于恢复流程与 run 结果）；
  - selectSession 恢复加固：withTimeout(8s) → sanitize → 与本地非空缓冲合并；失败降级 localStorage 镜像 → 空线程 + `restoreFailed[sid]` 标记（下次进入自动重试）+ 非阻断警示；任何分支都不清空已有记录；
  - connectedCallback：会话列表带超时+重试一次，最终失败降级为镜像索引渲染；成功时用索引补齐服务端缺失会话入口；
  - rename/delete 同步维护镜像索引（防幽灵会话复活）。
- 验证：webapp tsc EXIT=0；chat-history 单独编译后 Node 跑 16 项运行时断言全过（消毒/往返/配额降级/损坏信封/重叠合并/purge/超时）。
