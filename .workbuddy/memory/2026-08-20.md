## Render 部署失败（同日，L1 引发的连锁）
- **现象**：Render build 在 `pnpm install` 阶段 exit 1，栈帧 `runDepsStatusCheck → runPnpmCli → execaCoreSync → spawnSubprocessSync`。
- **根因**：L1 把 `playwright-core` 从根 `package.json` 删除，但**未同步 `pnpm-lock.yaml`**（其 `importers/./packages/snapshots` 三处仍残留 `playwright-core@1.62.1`）。pnpm 的 `runDepsStatusCheck` 内部派生 `pnpm install --frozen-lockfile` 子进程校验依赖状态，lockfile ≠ package.json 时该子进程直接 exit 1，炸在外层 install 上。
- **修复**：`NODE_OPTIONS="--use-system-ca" pnpm install --no-frozen-lockfile --lockfile-only --prefer-offline` 重生成 lockfile（仅删 playwright-core，+1/-12 行）。随后 `pnpm install --frozen-lockfile --lockfile-only` exit 0 验证通过。
- **教训（重要）**：在 pnpm monorepo 中**改 `package.json` 依赖必须同步 `pnpm-lock.yaml`**，否则 Render/CI 的 frozen 校验必挂。`render.yaml` 的 buildCommand 虽写 `--no-frozen-lockfile`，但 `runDepsStatusCheck` 的子进程仍走 frozen 校验，绕不过去。

## RAG 接入 agent-harness（MCP_SERVERS 最通用落地，同日）
- **落地点选择**：用「仓库根 `.env`」作为最通用单一来源——它被 `server.ts:109 loadSecrets()` 自动注入 `process.env`，本地 dev 与 docker-compose（`${VAR:-}` 从宿主 .env 注入容器）通用；Render 用同名 `envVars` 复用同一键（平台 env 优先级最高，不被 `.env` 覆盖）。三处同源复用 `MCP_SERVERS` 键。
- **env 替换陷阱（关键）**：MCP stdio 子进程 `StdioClientTransport({command,args,env})` 把 `env` 透传给 `spawn`，SDK 用 `this._env ?? process.env`——**只要 per-server `env` 字段非空即整体替换子进程环境，node 因丢失 PATH 无法启动**。因此 `RAG_TRANSPORT=mcp` / `RAG_TENANT_ID` / `RAG_DATA_FILE` 必须作为**顶层 env** 注入，由 RAG 子进程继承（仅 RAG 读取，对其他 MCP 无副作用）。MCP_SERVERS 条目仅含 `name/command/args`，不写 env 子字段。
- **配置内容**：`MCP_SERVERS='[{"name":"rag","command":"node","args":["services/rag/dist/index.js"]}]'`（JSON 单引号包裹，兼容项目 parseDotenv 与 docker-compose .env 解析）；已写入根 `.env`、`docker-compose.yml`(ui.environment)、`render.yaml`(envVars)。RAG 子进程注册工具 `rag__rag_retrieve` / `rag__rag_ingest`，业务零改动。
- **验证**：① `.env` 经 parseDotenv 后 `JSON.parse` 成功，entry.name=rag/command=node/args 正确；② smoke 脚本以 `RAG_TRANSPORT=mcp` 启动 RAG 子进程，走 `initialize→tools/list`，返回 `rag_retrieve, rag_ingest`，stderr 打印 `[rag] MCP server (stdio) ready, tenant=default` → SMOKE_OK。
