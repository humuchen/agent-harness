## Render 部署失败（同日，L1 引发的连锁）
- **现象**：Render build 在 `pnpm install` 阶段 exit 1，栈帧 `runDepsStatusCheck → runPnpmCli → execaCoreSync → spawnSubprocessSync`。
- **根因**：L1 把 `playwright-core` 从根 `package.json` 删除，但**未同步 `pnpm-lock.yaml`**（其 `importers/./packages/snapshots` 三处仍残留 `playwright-core@1.62.1`）。pnpm 的 `runDepsStatusCheck` 内部派生 `pnpm install --frozen-lockfile` 子进程校验依赖状态，lockfile ≠ package.json 时该子进程直接 exit 1，炸在外层 install 上。
- **修复**：`NODE_OPTIONS="--use-system-ca" pnpm install --no-frozen-lockfile --lockfile-only --prefer-offline` 重生成 lockfile（仅删 playwright-core，+1/-12 行）。随后 `pnpm install --frozen-lockfile --lockfile-only` exit 0 验证通过。
- **教训（重要）**：在 pnpm monorepo 中**改 `package.json` 依赖必须同步 `pnpm-lock.yaml`**，否则 Render/CI 的 frozen 校验必挂。`render.yaml` 的 buildCommand 虽写 `--no-frozen-lockfile`，但 `runDepsStatusCheck` 的子进程仍走 frozen 校验，绕不过去。

## 沙箱踩坑（可复用）
- `pnpm -r build` 因移除 playwright-core 触发隐式 `pnpm install` 重链接，卡 EPERM（`.modules.yaml` + `.bin` 软链）。绕过：直接 `node packages/<pkg>/node_modules/typescript/bin/tsc -p .../tsconfig.json` 编译。
- `tsc -p` 原地 emit 到 `dist/` 会**静默 exit 1**（无任何输出）——根因是 `dist/` 里个别文件（如 server 的 `run-queue.js`）被残留进程/守卫占用无法 unlink/覆盖。有效绕过：`--noEmit` 先做类型检查定位错误；emit 到临时 `--outDir`，再 `rm -f dist/*.js dist/*.d.ts`（单文件 rm 可删）后重新原地 emit，或对个别改动文件 `rm -f` 后从临时产物 `cp` 回填。

## docs/07-rag 整体架构 Mermaid 渲染失败修复（同日）
- **现象**：`docs/07-rag/external-rag-design.md` 第 2 节「整体架构」flowchart 在 Markdown 预览器里渲染失败（红块/不显示）。
- **根因**：① 节点标签裸用特殊字符——`PARSE[解析 & 清洗]`、`RET[检索编排: 混合检索 + 重排]` 里的 `&` 被 Mermaid 当成「并行运算符」（`A & B --> C`）触发解析错误；`+`/`:`/`/` 在裸标签里也脆弱。② 链式边 `GW -->|检索结果 JSON| MCP --> GUARD --> LLM` 把「带标签边」和「无标签链式」拼在一行，部分 Mermaid 版本报语法错。
- **修复**：所有含特殊字符的标签统一用**双引号包裹**（如 `PARSE["解析 & 清洗"]`、边标签 `LLM -->|"rag_retrieve 工具调用"| TOOL`）；链式边拆成独立语句（`MCP --> GUARD` / `GUARD --> LLM`）。另用 Visualizer 渲染了一张等价的深色 SVG 架构图供即时核对。
- **可复用经验**：写 Mermaid 时，中文标签一旦含 `&`、`:`、`+`、`/`、`()` 等，务必用双引号包裹节点/边标签，否则易渲染失败。sequenceDiagram 的消息文本（`:` 之后）对 `+`/`/` 较宽容，但若也失败，优先同样处理或改扁平写法。
