## 修复 CI 部署逻辑（用户确认「CI 部署确实有问题，请修复」）
- 根因：`.github/workflows/deploy.yml` 只把静态 `public/` 推到 GitHub Pages，
  而 `/api/*` SSE 后端在 `src/ui/server.ts`（仅本地 node），Pages 上线后页面无法真正运行。
  前端另有一处真实 bug：`refreshMcp()` 的 `var p` 声明在 `.then()` 内、却在 `.catch()` 引用 → fetch 失败时 ReferenceError，MCP 面板卡死。
- 用户选定方案：**做成可交互的静态演示**（对齐项目「一切降级可用」哲学）。
- 改造 `public/index.html`：
  - 新增 `window.HarnessDemo` 模块，在浏览器内复刻与真实 SSE 一致的事件流
    （run/verify/env 三类脚本，事件类型·字段名·护栏规则·状态机时序对齐 src/ 实现），entry 护栏命中密钥直接拦截。
  - 新增 `Backend` 适配层：`probe()` 探测 `/api/state`，存活则走 `realStream`（原 SSE 解析），
    否则路由到 `window.HarnessDemo`；`getJSON/stream` 统一口径。
  - 修复 `refreshMcp` 的 `p` 作用域 ReferenceError，并改为走 `Backend.getJSON`；演示模式下隐藏「添加 MCP」表单。
  - 加载时探测后端，缺失则展示「静态演示模式」横幅、chips 标 `.demo` 紫色。
- CI 加固：
  - `deploy.yml` 增加 `npm ci` + `npm run build`（tsc 类型检查门禁）+ 内联 JS 语法校验，未通过不发布。
  - 新增 `ci.yml`：所有分支 push + PR 跑 `npm ci` + `npm run build` + `npm run verify:harness`（离线注入假 fetch，无需密钥/网络）。
- 验证：节点内功能测试 demo 模块（run/verify/env 终态事件均触发、guardrail 拦截生效）；
  `npm run build` 与 `npm run verify:harness` 本地通过；启动 `npm run ui` 确认 `/api/state` 200、`/api/run` SSE 帧格式与解析器匹配（live 路径未受影响）。
