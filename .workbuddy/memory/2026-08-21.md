## 医美插件 knowledge → RAG 迁移（按用户方案1「把knowledge去掉」）

- 新增 `plugins/medical-aesthetics-lead/scripts/rag-ingest.cjs`：复用 `services/rag/dist` 的 `MemoryVectorStore/createEmbedder/ingestDocument`，把 knowledge/ 母版灌入 RAG 向量库并持久化到 `rag-store.json`（默认 `MA_DATA_DIR/rag-store.json`，gitignored）。project-catalog 逐项目拆成结构化 doc，元数据带 `complianceReviewed/compliantCopy/summary` 等以保留合规闸门；其余 md/json 作为 reference doc。

- `src/services/kb-service.ts`：`searchProjects` 优先 `cfg.rag.enabled` → `searchProjectsRag()` 调 RAG `/v1/retrieve`，对 `type==='project'` chunk 由元数据重建 ProjectRecord（保留合规闸门），reference chunk 作为 refs；未配 RAG 回退本地库 ma_project（安全）。新增 `RagRef`/`RagSearchResult` 类型。
- `src/tools/kb.ts`：`project_kb_search` 在 `rag.enabled` 时走 `searchProjectsRag`，返回 projects + refs；注释更新。

- `docs/CONFIG.md`：kb-seed 启用步骤改为 rag-ingest；脚本表移除已删 4 个、保留 kb-smoke。

- 插件 `tsc -p tsconfig.json` 零错误（EXIT=0）。

### 注意 / 陷阱
- `rag-store.json` 是迁移后**运行时唯一持久化知识源**，且 gitignored；`knowledge/` 已删除，故 `rag-ingest.cjs` 现已无法重跑（判定 knowledge/ 不存在并安全退出）。新环境重建需复制该 store 文件，或保留 knowledge/ 母版后再迁移。已用 `git checkout` 恢复过一次 knowledge/ 以重跑灌库——后续若需重建务必先恢复或备份 knowledge/。
- RAG 服务开放模式：无 `RAG_TOKENS`/`RAG_API_TOKEN` 时 `resolveTenant` 返回默认租户 `default`，与 ingest 写入租户一致；kb-service 不传 token 即可检索。
- 维度一致性：ingest 与 RAG server 共用 `createEmbedder()`（默认 HashEmbedding dim=256），验证时显式设 `RAG_EMBED_DIM=256` 并关闭 `RAG_EMBEDDING_API_KEY` 以避免维度不匹配导致 load 抛错。
- Git Bash 路径坑：`rm -rf /c/Users/...` 与 `C:/Users/...` 同目录，曾误删已生成的 rag-store.json；重跑时务必用 `MSYS_NO_PATHCONV=1` + 绝对 Windows 路径 + `MA_RAG_DATA_FILE` 显式指定。
