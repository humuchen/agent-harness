1. Agent 注册 & 发现层

AgentRegistry
`backend/core/src/agents/registry.ts`
- 倒排索引：capability → agentId

AgentCard
`backend/core/src/agents/types.ts:64`
- id, name, domain
- assembly.{systemPrompt, skills, tools, mcpServers}
- isolation（none/os/container）
TaskRouter
`backend/core/src/router/router.ts`
路由优先级：
1. agentId 直接寻址
2. domain 过滤 + 打分
3. classify 意图分类
4. fallback → default
↓ 注册 / 查询 API ↓

• project-advisor

2. 运行 & 派发层

run-queue
`access/server/src/run-queue.ts`
- 4 优先级：urgent > high > normal > low
- 并发上限：RUN_CONCURRENCY=4
- 同 sessionKey 串行化
- 事件重放缓冲（RUN_QUEUE_BUFFER=500）
assembleAgent
`access/server/src/runner.ts:259`
- 按 card.assembly 收窄工具面
- 注入 delegate_task 子 agent 工具
- 租户隔离：tenantSessionKey
- 护栏作用域：deriveGuardrailScopes(card)
SSE /api/run
`server.ts:2767`
- job:accepted → jobId
- llm:token → 流式回复
- llm:usage → 上下文用量
- run:end → 终态
↓ delegate_task ↓
delegate_task 工具
`subagent-tools.ts:53`
参数：task, agent, maxSteps, timeoutSec
- 递归 assembleAgent()
- 独立 sessionKey：wf:parent::child
- 独立 AbortController + 超时
- 图片附件透传 ✅
SubAgentManager
`backend/core/src/subagent.ts`
- create / markRunning / complete / fail / cleanup
- 单例，支撑 agent 树形追踪
runAgentTask
`access/server/src/agent-run.ts:29`
- 本地执行 agent 任务的最终落点
- 租户隔离 + sessionKey：tenant::a2a:card.id
- 被 workflow、A2A、handoff 复用

3. 工作流编排层

DagEngine
`backend/core/src/workflow/dag.ts`（推测）
- 拓扑排序 + 依赖分析
- validateWorkflow() fail-fast
- compensate 回滚支持
WorkflowExecutor
`access/server/src/workflow-executor.ts:34`
- agentRef → 单 agent 执行
- teamRef → TeamManager 并发执行
- wf:wfId:stepId sessionKey 隔离
- 事件透传 SSE
TeamManager
`backend/core/src/teams/index.ts`
模式：sequential | parallel | round-robin | competitive
- 成员存在性校验
- executeTask(teamId, input, dispatch)
↓ /api/workflows ↓
POST /api/workflows
`server.ts:2408`
WorkflowDef = { id, steps }
每步：agentRef, inputMapping, dependsOn
SSE 直播：wf:step:start/done
GET /api/workflows/:id
`server.ts:1754`
- 执行快照查询
- POST /api/workflows/:id/resume 断点续跑
