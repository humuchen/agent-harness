# 医美 Agent 落地 · 第 0 步并行清单（资质申请 + CRM 选型）

> 对应补齐计划的「第 0 步：立即并行」。这些是**外部动作**，审批周期长，必须在开发第 1-3 步期间同步推进；
> 不启动则第 4 步（渠道适配）与第 5 步（CRM 读取）永远无法开工。

## 一、平台资质申请（抖音 / 小红书 / 美团私信官方 API）

**原则：只走官方开放平台 API，绝不脚本模拟（防封号红线）。**
现有 `access/server/src/im/` 的企微/飞书/钉钉适配器范式可直接复制，新渠道只需实现同一适配器契约。

### 1. 抖音（抖音开放 platform.open.douyin.com）
- [ ] 企业主体资质：营业执照、医疗美容机构执业许可（医疗类目强制）
- [ ] 「企业号」认证 + 开放平台开发者入驻
- [ ] 申请「私信消息」能力（IM API：收私信/回私信/群发受严格限制）
- [ ] 申请「留资卡片/线索通」组件（官方卡片留联系方式 = 合规分水岭，替代私信里直接收手机号）
- [ ] 医疗健康类目额外审核：内容需过平台医疗合规（疗效词禁用与我们 `medical-ad-guard` 同向）
- ⚠️ 注意：医疗类目私信 API 权限收紧，若「私信回复 API」不可批，先用「留资卡片的线索推送 API」（获客-线索接口）兜底

### 2. 小红书（专业号平台）
- [ ] 专业号认证（企业号）+ 聚光/私信通开通（私信 API 隶属「私信通」付费能力）
- [ ] 申请私信接口权限（自动回复 + 留资组件）
- [ ] 医疗美容为限流类目：确认机构可开通的私信自动化等级
- ⚠️ 私信通未开通时，只能人工接待 —— 先申请，落地顺序可后置

### 3. 美团/点评（到店转化导向）
- [ ] 医美机构入驻 + 开放平台应用创建
- [ ] 申请「咨询消息/IM」接口（美团开店宝咨询 API）
- [ ] 到店核销 API（`arrived` 闭环回写用，对应现有 `ma_appointment`）

### 通用注意
- 每个平台的「消息主动触达」都有频控与场景限制：我们的调度器（第 1 步）已按「沉默 2h/24h、每节点至多一次」设计，接入时在渠道适配器内再加平台侧限流参数即可
- 所有渠道回调统一走 `POST /webhook`（HMAC 验签已内建），新渠道只需扩展 `channel` 字段与验签方式
- 申请材料通常需要「隐私政策/用户授权页」：与插件 `lead_capture` 的明示授权话术保持一致

## 二、CRM 选型（第 5 步 C6/C7 的前置）

**现状**：插件已有出站同步（`crm-client` → `POST {CRM}/v1/leads`，幂等键 + 发件箱至少一次投递）。
选型只需满足**读回接口**即可补全「CRM 读取回传」缺口。

### 必选评估维度
- [ ] **开放 API 双向**：既有「线索写入」也有「线索/客户读取」（`GET /v1/leads/:id` 或 webhook 推送变更）
- [ ] **自定义字段**：能存 grade/stage/project/channel 等插件字段（或字段映射能力）
- [ ] **Webhook 回推**：CRM 侧状态变更能推回 `POST /callback`（type=lead.status 已内建）
- [ ] **权限与审计**：lead:read/lead:assign/lead:export 对应的 RBAC（平台 `authz` 已预留 guard 动作）
- [ ] **PIPL 合规**：手机号脱敏/加密存储、授权留痕（`consent_at` 字段已落库）
- [ ] **部署形态**：SaaS（数据出机构）vs 私有化（医美客户普遍倾向私有化）
