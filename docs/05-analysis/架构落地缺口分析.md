## 2. 历史缺口清单（已全部补齐）

> 以下为演进过程中的缺口快照，**截至 2026-08-21 已全部补齐**（对应实现见 §0 映射表）：前端 `useAgentContext`/Suggestions/文件上传/Popup/会话状态机、接入层 `ReplicaPicker` 应用层负载均衡、后端工具层 `defineTool` 声明式 API 与 `builtin__weather`/`builtin__data_transform`。WebSocket 端点因「零外部依赖」约束未引入 `ws`，维持 HTTP+SSE。保留原文作为演进记录。

以下按"所属分层 → 预期职责 → 缺失的具体实现"逐条列出（**现状：均已补齐**）。

### ① 前端应用层 · `useAgentContext` 跨组件状态共享
- **预期职责**：在 Chat UI、交互组件、会话管理之间共享统一的应用状态（会话、运行态、事件流），避免 prop 透传与重复拉取。
- **缺失实现**：webapp 基于 **Lit**（`@agent-harness/webapp` = Lit + Vite SPA），**无 React Context 或 `useAgentContext` hook**。当前状态共享由各组件 `@state()` 装饰器 + `@agent-harness/client` SDK 各自拉取/缓存（如 `app.ts`、`chat.ts`、`dashboard.ts` 各自 `getState()`）。缺少一个统一的应用级状态容器（store / context）来跨组件共享运行态与事件流。

### ② 前端应用层 · Suggestions（建议/快捷指令）交互组件
- **预期职责**：在对话界面提供可点击的建议问题/快捷指令，引导用户意图、降低输入成本。
- **缺失实现**：`chat.ts` 中无 suggestion / quick-chip 渲染逻辑与数据源；`grep` 全源码未见 `suggest`/`建议`/`quick` 类实现。建议生成（静态列表或模型驱动）与 UI 入口均缺失。

### ③ 前端应用层 · 文件上传（File Upload）交互组件
- **预期职责**：支持用户上传文件/附件，供 agent 检索或作为工具输入（如知识库导入、文档问答）。
- **缺失实现**：webapp 无 `<input type=file>`、拖拽上传区、附件预览或上传 API 调用（`grep` 无 `upload`/`input type=file`/`附件`/`drag`）。即便后端有 `filesystem` 工具，前端**没有文件上传入口与通道**，该能力对用户不可达。

### ④ 前端应用层 · Popup（弹窗式聊天）形态
- **预期职责**：在 Sidebar 主面板之外，提供可嵌入宿主应用的浮层 / Popup 聊天入口（便于第三方站点嵌入）。
- **缺失实现**：聊天仅以整页面板 Tab（`ah-chat`）存在，无浮动 Popup 组件或嵌入脚本（embed snippet）。"Sidebar + Popup"双形态中的 Popup 未完成。

### ⑤ 前端应用层 · 会话状态机（业务编排/会话管理中的"状态机"）
- **预期职责**：以显式状态机刻画会话生命周期（idle / streaming / awaiting-human / completed 等），支撑复杂业务编排与可恢复流程。
- **缺失实现**：仅有 `run.ts` 的 `PHASES` 阶段跟踪（`pending`/`running`/`done`…）与 `chat.ts` 的 `streaming` 布尔位；**无跨组件共享的会话状态机定义与状态转移逻辑**，业务编排停留在"单轮 run"粒度。

### ⑥ 接入层 · 统一 API 网关的 WebSocket 端点
- **预期职责**：网关同时暴露 HTTP REST、SSE、WebSocket 三种协议；WS 作为双向实时通道（如服务端主动推送、双向控制）。
- **缺失实现**：`server.ts` 仅实现 HTTP + SSE（client 通过 `client/sse.ts` 消费流）；全源码**无 `upgrade` 握手 / WebSocket 端点**（唯一 `upgrade` 命中是插件版本 `upgrade`，非协议升级）。"WebSocket"能力未落地，网关实际为 HTTP+SSE。

### ⑦ 接入层 · 应用层负载均衡
- **预期职责**：接入层内置多副本水平扩展的负载均衡能力（如一致性哈希、健康探活、流量分发）。
- **缺失实现**：应用层无 LB 组件；水平扩展完全依赖外部基础设施（K8s Service / Docker / reverse-proxy）。严格来说属于"基础设施承载"而非接入层应用代码落地——若按架构图将其归为接入层能力，则该能力**未在应用层实现**。

### ⑧ 后端工具层 · `defineTool` 声明式工具封装 API
- **预期职责**：以 `defineTool(...)` 统一、声明式地封装 Server Tools（天气/知识库/计算…），降低新增工具的样板代码。
- **缺失实现**：全代码库**无 `defineTool` 符号**（仅出现在 SVG）。工具实际通过 `ToolRegistry.register` / Skill 定义注册。该"声明式封装"API/范式未以 `defineTool` 命名与形态落地（属封装范式缺口，非能力缺口）。

### ⑨ 后端工具层 / 外部集成 · 天气（Weather）第三方工具
- **预期职责**：作为 Server Tools 示例的"天气"能力，提供天气查询，并接入"天气/计算 等第三方"生态。
- **已实现**：`backend/core/src/builtins/weather.ts`（基于 open-meteo，零额外依赖）已落地，`builtin__weather` 工具随 `registerBuiltinTools` 注册，受 `BUILTINS_DT`/`BUILTINS_WEB` 等同级开关控制。原缺口分析中「全仓无天气相关源码」的判据已过时——"天气/知识库（RAG）/计算（calculator）"三示例现均已实现。

### ⑩ 后端工具层 · 数据处理（ETL / 格式转换 / 清洗）独立工具
- **预期职责**：提供一等的数据处理能力（ETL、格式转换、数据清洗），供 agent 在工具链中复用。
- **缺失实现**：无独立 data-processing 工具；数据处理仅**隐含**在 `webfetch`（抓取+解析）与 `filesystem` 读写中，未作为声明式、可发现的一等工具暴露，与架构图"数据处理"独立模块定位不符。

## 3. 小结

- **已大规模落地**：基座服务层（Registry/Tenant/Policy/Quota/Audit/Sandbox/Plugin 市场/Retention/Routing/Workflow/Agent Runtime）、执行后端层（含 A2A Transport）、接入层的路由/鉴权/A2A 自注册、后端工具层的第三方调用与底层能力封装——均已在当前代码中实现。旧评估（2026-08-15）的"缺失项"多数已被补齐。
- **§2 的 10 项缺口已于 2026-08-21 全部补齐**（见 §0 映射表）：前端补齐了跨组件状态容器（Lit 版 useAgentContext）、Suggestions、文件上传、Popup、会话状态机；接入层补齐了可复用的应用层负载均衡选择器 `ReplicaPicker`（round-robin / least-load / sticky-hash 一致性哈希）；后端工具层补齐了 `defineTool` 声明式封装、`builtin__weather` 天气工具与 `builtin__data_transform` 数据处理工具。WebSocket 端点因"零外部依赖"约束未引入 `ws` 依赖，维持 HTTP+SSE。
- 上述补全全部遵循既有风格与约束（`builtin__` 前缀、`objectParams`、`allow(tools)` 收窄、`error: ...` 错误回灌、零外部依赖、参数校验 + 异常兜底），且均有对应测试与构建验证。
