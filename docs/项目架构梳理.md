# Agent-Harness 项目架构梳理

## 1. 项目概述

**Agent-Harness** 是一个基于 TypeScript 构建的 **AI Agent 调度基座框架**。它采用 `pnpm monorepo` 组织代码，旨在提供一个从单智能体执行引擎到多智能体协作、行业租户隔离、任务路由及工作流编排的统一基础设施。

该项目不仅支持单个 Agent 的自动闭环执行，还提供了企业级的多租户管理、合规策略、沙箱隔离以及可观测性能力，适用于金融、医疗、教育等对安全性和流程控制有严格要求的场景。

---

## 2. 核心架构分层

项目架构自顶向下分为五层，各层职责清晰，通过标准接口解耦：

### 2.1 接入层 (Access Layer)

- **位置**: `access/server`, `frontend/webapp`, `frontend/cli`
- **功能**:
  - **HTTP + SSE API**: 提供标准的 RESTful 接口及 Server-Sent Events 流式输出，支持实时交互。
  - **Webapp SPA**: 基于 React/Vue 的单页应用，提供可视化的 Playground 供用户调试和监控 Agent 运行。
  - **CLI**: 命令行工具，支持本地快速启动、环境管理及任务提交。

### 2.2 路由编排层 (Routing & Orchestration)

- **位置**: `backend/core/router`, `backend/core/workflow`, `backend/core/a2a`
- **功能**:
  - **意图路由**: 对用户输入进行意图识别、评分，动态选择最合适的 Agent。
  - **工作流引擎**: 支持 DAG（有向无环图）编排，实现多步骤任务的并行执行、失败补偿及检查点续跑。
  - **A2A 协议**: 定义 Agent 之间的通信标准，支持多智能体协作网络。

### 2.3 智能体层 (Agent Layer)

- **位置**: `backend/core/agents`
- **功能**:
  - **AgentCard**: 标准化的 Agent 元数据声明（能力描述、输入输出规范）。
  - **AgentRegistry**: 负责 Agent 的注册、发现与生命周期管理。

### 2.4 基座服务层 (Foundation Services)

- **位置**: `backend/core/tenant`, `backend/core/policy`, `backend/core/quota`, `backend/core/audit`, `backend/core/sandbox`
- **功能**:
  - **多租户隔离**: 支持逻辑或物理隔离，确保不同租户数据独立。
  - **行业合规策略**: 内置金融、医美、医疗、教育等行业的特定策略画像。
  - **配额与计费**: 细粒度的 Token/调用次数配额管理。
  - **审计日志**: 全链路操作记录，满足合规审计需求。
  - **沙箱隔离**: 提供 OS 级或容器级沙箱，防止恶意代码执行。

### 2.5 执行后端层 (Execution Backend)

- **位置**: `backend/core/harness`, `backend/core/tools`, `backend/core/memory`, `backend/core/guardrails`
- **功能**:
  - **Harness Core**: 主循环控制器，驱动 Agent 的思考 - 行动 - 观察循环。
  - **工具注册表**: 统一管理外部工具（API、数据库、文件系统）的接入。
  - **记忆模块**: 管理短期上下文与长期记忆存储。
  - **三层护栏**:
    1. **输入过滤**: 拦截恶意提示词。
    2. **执行监控**: 运行时行为检测。
    3. **输出审查**: 确保回复符合安全规范。

## 3. 关键特性详解

### 3.1 单智能体自动闭环

- 具备**自愈能力**：当工具调用失败时，自动分析错误并尝试重试或切换策略。
- **三层护栏**机制贯穿始终，确保单次执行的安全性。

### 3.2 多智能体协作

- 基于**意图路由**将复杂任务拆解并分发给专业 Agent。
- 遵循 **A2A (Agent-to-Agent)** 协议，实现异构 Agent 间的无缝通信。

### 3.3 工作流编排

- 支持 **DAG (Directed Acyclic Graph)** 定义复杂业务流程。
- 特性包括：节点并行执行、失败自动补偿、断点续跑（Checkpoints）。

### 3.4 多租户与行业合规

- **租户隔离**: 灵活的隔离策略适配不同规模客户。
- **策略画像**: 预置行业合规模板（如 HIPAA 医疗合规、金融风控规则），可快速启用。

### 3.5 安全沙箱

- 支持 **OS 级沙箱** 和 **容器化隔离**，确保 Agent 执行的代码或访问的资源不会危害宿主环境。

### 3.6 MCP 集成 (Model Context Protocol)

- 已集成 **Context7** 等 MCP 服务器。
- 支持 **自动重连** 机制，增强上下文获取的稳定性。

### 3.7 自助环境治理

- 架构设计为 **可插拔** 模式，支持在 `local` (本地)、`harness` (框架托管)、`k8s` (Kubernetes) 等多种环境下无缝切换部署。

### 3.8 可观测性

- 集成 **OpenTelemetry**，支持自动降级策略。
- 提供详细的审计日志与实时告警能力。

## 4. 包结构说明 (Monorepo Layout)

```text
agent-harness/
├── packages/
│   ├── core/               # 核心框架库
│   │   ├── harness/        # 执行引擎主循环
│   │   ├── agents/         # Agent 定义与注册
│   │   ├── router/         # 意图路由
│   │   ├── workflow/       # 工作流编排
│   │   ├── tools/          # 工具集
│   │   ├── memory/         # 记忆模块
│   │   ├── guardrails/     # 安全护栏
│   │   ├── tenant/         # 租户管理
│   │   ├── policy/         # 策略引擎
│   │   ├── quota/          # 配额管理
│   │   ├── audit/          # 审计日志
│   │   └── sandbox/        # 沙箱环境
│   ├── server/             # HTTP 服务入口
│   ├── webapp/             # 前端可视化界面
│   ├── client/             # SDK 客户端
│   ├── cli/                # 命令行工具
│   └── examples/           # 示例代码与场景演示
├── docs/                   # 完整文档目录
└── pnpm-workspace.yaml     # Monorepo 配置
```

## 5. 快速开始与验证

### 5.1 启动服务

在项目根目录下，使用 pnpm 安装依赖并启动服务：

```bash
pnpm install
pnpm dev
```

### 5.2 访问 Playground

服务启动后，访问可视化界面验证功能：

- **地址**: [http://localhost:4173](http://localhost:4173)
- **功能**: 在此界面可创建任务、选择 Agent、查看执行日志及拓扑图。

### 5.3 文档查阅

完整的 API 文档、架构设计图及开发指南位于 `docs/` 目录下。

## 6. 总结

Agent-Harness 不仅仅是一个 Agent 运行器，它是一个**企业级的 AI 应用操作系统**。通过分层架构设计，它成功地将底层的执行细节、中间的路由编排与上层的业务场景解耦，既满足了开发者对灵活性的需求，又提供了企业所需的安全、合规与可观测性保障。

无论是构建简单的问答机器人，还是复杂的跨部门自动化工作流，Agent-Harness 都能提供坚实的基座支持。
