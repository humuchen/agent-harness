关键判断：表格问题的本质不是「模型没输出表格」，而是「表格渲染被一条 display:block 规则降级成了裸文本流」。修复只需补齐 9 条 CSS 规则 + 一层 wrapper， 无需更换解析器。

1表格适配：从「裸文本流」到「可读数据表」

设计目标：① 表头与数据列严格对齐；② 长内容可读、宽表不撑破气泡；③ 移动端可用； ④ 不破坏 table 语义（屏幕阅读器要求）。

1.1 DOM 结构改动：引入滚动 wrapper

现状直接在 table 上做滚动，必须写 display:block， 代价是语义与布局双双降级。正确做法是「外层滚动、内层保语义」：

方案实现评价
现状 table { display:block; overflow-x:auto } 丢失表格布局算法，列宽由内容随机决定；圆角/边框无法与表体协调。否决
提案 在 renderer.table() 中输出 <div class="md-table-wrap"><table>…</table></div>； wrapper 承担 overflow-x:auto + 边框 + 圆角。 table 保留 display:table，列宽由表格算法分配； 圆角由 wrapper 裁剪（避开 border-collapse 与圆角冲突）。 采纳
加分项（低成本高收益）：wrapper 上叠加 data-cols 与横向渐隐遮罩， 当表格宽度超出气泡时，右侧出现渐变提示「可横向滚动」，解决「用户不知道能滑」的可发现性问题。

1.2 呈现规范（可直接落地的 9 条规则）

#属性取值与设计理由

1.5 大表格折叠（可选增强）

模型常一次输出 20+ 行表格，会把对话流彻底淹没。建议：行数 > 12 时默认折叠到 8 行， 底部给「展开全部 24 行」按钮。折叠阈值与行高需与流式打字机协同——流式期间不折叠（避免高度反复跳动）， 消息进入完成态后再应用折叠。

2代码高亮：从「等宽纯文本」到「可读、可复制、可定位的代码块」

设计目标：① token 着色且明暗主题一致；② 代码不折行、语义不被破坏；③ 可一键复制； ④ 语言标注可信（不猜、不误着色）；⑤ 不突破现有 XSS 防线。

2.1 高亮方案选型

方案体积量级主题模型关键取舍结论
highlight.js core + 按语言按需注册，可控在数十 KB 量级（须实测打包产物标定） 输出 class="hljs-*" 唯一产物是 class → 可由 CSS 变量完全接管配色，天然适配 [data-theme] 双主题； 同步 API，可在流式渲染路径中直接调用。 推荐
Shiki 含 TextMate 语法与 wasm 引擎，量级显著更大 倾向输出 inline style 或 CSS 变量 着色最忠实（VS Code 原生级），但初始化重、需异步或 Worker； 且 inline style 会迫使 DOMPurify 放开 style 白名单， 直接扩大注入面。 不推荐
Prism.js core 极轻，语言按需 输出 class 体积最优，但语言定义覆盖面与 hljs 有差距，且需自行处理转义与 autoloader 复杂度。 备选
自研正则 0 完全可控 无新增依赖，但每种语言都要自己写规则，长期维护成本高于收益，且极易在字符串/注释中误着色。 不推荐
决策建议：采用 highlight.js/lib/core + 白名单注册约 12 种高频语言 （python / typescript / javascript / bash / json / sql / go / java / rust / yaml / diff / xml / css / markdown）， 其余语言一律降级为纯文本块而不引入完整包。收益：体积可控、主题可随 --ah-* 令牌切换、安全面不扩大。

2.2 集成链路：高亮必须发生在净化之前

这是本设计最容易踩错的一步。若在 DOMPurify.sanitize() 之后再做高亮， 代码文本已经变成 &lt; 这类实体，token 边界不可恢复； 因此高亮必须挂在 marked 的 renderer.code 里， 由净化层统一兜底。

typescript复制
// utils/markdown.ts（提案实现，marked@12 的旧签名：code(code, infostring, escaped)）
const md = new Marked({
  gfm: true,
  breaks: false,
  renderer: {
    code(code, info) {
      const lang = (info || '').trim().split(/\s+/)[0].toLowerCase();
      // 未知语言一律不着色：错误着色比无色更误导
      const html = hljs.getLanguage(lang)
        ? hljs.highlight(code, { language: lang, ignoreIllegals: true }).value
        : escapeHtml(code);
      // 按钮必须出现在 HTML 字符串里：流式每 tick 全量重渲染，渲染后再注入的 DOM 会被抹掉
      return `<div class="code-block" data-lang="${escapeHtml(lang || 'text')}">
        <div class="cb-head">…<button class="cb-copy" type="button" aria-label="复制代码">复制</button></div>
        <div class="cb-body"><pre class="cb-lineno"><code class="hljs">${html}</code></pre></div>
      </div>`;
    },
    table(header, body) {
      // wrapper 承担滚动与圆角，table 保留 display:table 语义
      return `<div class="md-table-wrap"><table><thead>${header}</thead><tbody>${body}</tbody></table></div>`;
    }
  }
});
安全约束（不可让步）：
  • 高亮产物只能输出 class，禁止 inline style，并在净化配置中显式 FORBID_ATTR: ['style']，防止后续改动把 style 白名单悄悄放开。
  • 净化白名单需显式包含 span / div / figure 与 class / data-lang / align / colspan / rowspan； 其余一律沿用 DOMPurify 默认拒绝策略。
  • 外链继续补 target="_blank" rel="noopener noreferrer"（marked 不会自动加）。

3.1 流式渲染稳定性 P0

现状是打字机逐帧输出 + 每帧对全文重新执行 toRichHtml()（全量 innerHTML 替换）。 这带来两个必现问题：

问题触发条件设计对策
未闭合围栏吞内容 模型正在输出 ```python 块，闭合标记尚未到达 → 其后所有文本被当作代码块内容，样式整段错乱。 渲染前做容错解析：检测未闭合围栏并补尾闭合标记（仅在渲染副本上），使已到达部分按代码块正确呈现，闭合后自然收敛。
半截表格抖动 GFM 表格在「分隔行 |---|---|」到达前不是表格，到达瞬间整块重排，气泡高度跳变。 流式期间对疑似表格（连续含 | 的行 ≥2）预留最小高度；或延迟到分隔行到达后再升级为表格（避免先渲正文后跳变）。
每帧全量重解析 长回答（数千字）时，每帧 marked + 高亮全量执行，帧耗时随文本线性增长。 ① 高亮按块级缓存（key = 块内容 hash），未变化的代码块复用上次 HTML；② 对超长块在流式期降级为纯文本，完成态再补高亮。
性能预算（建议写入验收标准）：单次 toRichHtml()（含高亮）在 4 核移动端设备上 P95 < 8ms； 流式期间若单帧超过 4ms，自动进入降级模式（跳过超长块高亮 + 关闭行号），消息完成后再补齐。

3.2 HTML 直出表格的降级缺陷 P1 · 已确认

已定位的真实缺陷：utils/html-safe.ts:19 的 MD_HINT 启发式只识别 Markdown 语法特征（含 | 管道、#、``` 等）。 当模型直接输出原始 HTML 表格（<table><thead>…）而全文不含任何 Markdown 标记时， isMarkdownLike() 返回 false → 走 escapeHtml() 分支 → 表格以源码文本形式显示在气泡里。

对策：在 MD_HINT 中补充块级 HTML 标签识别 （<table|<ul|<ol|<pre|<blockquote|<h[1-6]|<details|<div 等）， 命中即走富文本渲染路径，最终仍由 DOMPurify 兜底。 需注意副作用：用户投诉「我贴的代码被渲染了」这类场景会增多 → 需同时确保用户消息与 助手消息采用不同策略（用户粘贴内容默认按纯文本 + 转义呈现，助手输出才做富文本渲染），这是本项改造的隐含决策点。

3.3 跨容器一致性 P1

同一份富文本目前落在四个容器：对话气泡 .msg-text、 运行详情 .codeblock.rich、思考轨迹 .trace-block .tb-body、 置信度面板 .conf-reasons。建议抽出单一富文本样式源（如 styles/richtext-core.ts），四处以相同选择器基类引用，仅保留各自必要的覆盖（如轨迹块内的字号缩小）。

  • 收益：表格/代码规范一次定义、四处生效，避免「对话里好看、详情里不生效」的返工。
  • 成本：.msg-text 现依赖父级作用域，抽公共样式需确认与 chat-styles.ts 的组合顺序不冲突（该文件注释明确要求「顺序不变 ⇒ 层叠零变化」，改动需回归验证）。
  • 迁移建议：分两步——先让四处样式取值一致（拷贝同一组规则），确认视觉无回归后再做物理抽离。

3.4 可访问性与语义 P2

  • 表格不使用 display:block：现代屏幕阅读器依赖 table 的隐式角色，本次 wrapper 方案顺带修复了这一语义退化。
  • 代码块容器加 tabindex="0" role="region" aria-label="代码块：python"，使横向滚动区可被键盘聚焦滚动（否则键盘用户无法查看长行）。
  • 复制按钮使用真实 <button> + aria-label，复制成功态通过 aria-live="polite" 播报，而非仅靠图标变化。
  • 配色对比度：--tk-op（标点弱化色）在暗色底上需保持 ≥ 4.5:1，若实测不足则仅用于标点、不用于标识符。

3.5 行内代码与块级代码的解耦 P2

现状 .msg-text pre, .msg-text code 合用一条规则（pre-wrap）， 导致行内 `code` 与块级代码行为被绑定。改造后必须拆为两套： 行内 code 保留 pre-wrap（长标识符需要折行）+ 底色胶囊；块级代码改 pre（不折行）。 同时行内 code 的底色在对话气泡（--ah-surface-2）上会对比不足， 建议改用 --ah-surface-3 或 color-mix 微调，视觉验收时以截图比对确认。

6.1 折叠：两套容器，一个状态源

折叠入口的形态按容器各自的可用空间决定，但状态只有一份：

块类型入口位置阈值与默认态
代码块 工具条右侧（与「复制」并列） 超过 CODE_FOLD_LINES = 20 行 → 默认折叠，裁切高度 320px（窄屏 260px）
表格 表格下方独立折叠栏 超过 TABLE_FOLD_ROWS = 12 行数据 → 默认折叠，裁切高度 300px（窄屏 240px）

为什么折叠态必须住在组件 @state 里（而不是点击时改 DOM、也不是写进渲染产物字符串）：

  • 不能写在 DOM 上：.msg-text 经 unsafeHTML 注入， lit 无法 diff 其内部 —— 任何一次组件更新（hover、其他消息追加、流式 token 到达）都会重建整段 DOM， 写在 DOM 上的类名必然被抹掉，表现为「点开又自己合上」。
  • 不能写进产物字符串：产物是按文本内容缓存的纯函数结果， 把交互态混进去会让缓存命中率归零，且流式中每帧都会弹回默认折叠。

于是拆成两半：渲染产物只输出稳定标识（data-md-block="code:0" 与 data-md-lines、data-md-foldable）， 消息作用域由容器给（data-md-scope="ans-12"）； 组件在 updated() 里按 mdFolded 重放折叠类、按钮文案与 aria-expanded。 这样产物的缓存键仍只含文本与选项位，与用户点了什么完全无关。

6.2 修正：高亮放在净化「之后」更安全

项设计稿原口径实际实现与原因
注入时机 必须在 DOMPurify 之前注入 修正为：净化之后。 原顾虑是「净化后代码已成 HTML 实体、token 边界不可恢复」—— 这个顾虑只在「在不透明产物上做高亮」时成立。实际取的是已净化 DOM 的 textContent（解码后的完整原文），hljs 可重新分词， 边界并未丢失。反过来还能省掉一次 DOMParser， 且写回的是 hljs 自身转义过的输出、写回前再过一次净化，注入面更小。
验收脚手架缺陷
已记录		 未预料 chatStyles 在 A 批拆分后已变为 CSSResult[] 数组，直接取 .cssText 会得到 undefined，注入后聊天样式整段失效且无任何报错 （页面看起来像「样式莫名不生效」，极易误判为产品缺陷）。 须逐项 map(c => c.cssText) 再拼接。

6.3 五处取舍（做与不做）

项结论理由
行号 不做 需把 code 逐行包裹元素，破坏 hljs 输出的紧凑结构； CSS 计数器无法作用于「文本行」这一不存在盒模型的对象； 且行号文本会被 textContent 一并复制进剪贴板。收益低于成本。
语言自动检测 不做 highlightAuto 需对每块试跑全部已注册语言， 与流式帧预算（P95 < 8ms）直接冲突；且 JSON / JS / TS 之间误判率不低 —— 错误着色比不着色更误导。只有显式标注且在白名单内才着色。
高亮与容器拆成两个开关 不拆 「高亮但无代码块容器」= 彩色 token 直接落在气泡底色上， 看起来像误染色、且失去代码块的视觉边界，比无色更糟。两者是一套完整形态，不做半套。
折叠遮罩收尾色 用不透明色 渐变收尾若用 transparent 或半透明色， 被遮住的内容会以半透明形式透出，像渲染故障；改用 var(--ah-code-bg) / var(--ah-surface-1) 收尾。
流式中的折叠入口 不提供 内容仍在增长，中途被收起会让读者丢失阅读位置。折叠入口仅在消息定型后出现 （finalize 由 isStreamingAssistant / isThinking 推出）。
