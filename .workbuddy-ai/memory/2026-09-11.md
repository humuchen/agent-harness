### 5. 图片失效态附件交互设计稿 — 已完成（待评审）

用户反馈：图片不存在/加载报错时，消息附件区 5 个破图图标与文件名 alt 文本互相重叠，完全不可读。

根因定位：
- 渲染入口 `frontend/webapp/src/chat-message-render.ts:161` → `renderImageAttachments()`
- 实现 `frontend/webapp/src/chat-render-utils.ts:60-136`：多图折叠态用
  `translate(calc((--i - --mid) * 20px), calc(--i * 4px)) rotate(calc((--i - --mid) * 4deg))` 交错堆叠
  5 个 `<img>`（样式 `chat-styles.ts:3230-3262`）。
- `<img src>` 失效时浏览器渲染「破图图标 + alt 文本」，而 `alt=${escapeHtml(f.name)}` 恰好是文件名 →
  5 层文件名随层叠变换互相叠加。**根因：无 `@error` 兜底 + alt 承载了本该由占位卡承载的信息。**
- 单图分支（`chat-render-utils.ts:68-78`）同样没有失败态。

设计方案（四态，已出可交互设计稿，含「现状」对比页）：
- A 单图失效：与缩略图同尺寸的虚线占位卡（零布局抖动）+ 破损图标 + 「图片已失效」+ 文件名单行 ellipsis
  + 右上角 `!` 角标；hover 出「重试 / 复制文件名」。
- B 多图**全部**失效：不再堆叠 N 个破图，退化为**单张汇总卡**（三层缩进虚线 + 「5 张图片无法加载」+ 原因
  + 「查看」），点击展开为逐项占位网格（每项可单独重试）。
- C 多图**部分**失效：保持层叠位置不变，失败项在层内渲染为占位瓦片，角标改
  「5 张 · 3 张失效」并用警示色（amber `#BA7517`）；展开网格逐项区分成功/失败。
- D 输入区上传失败：`.attach-preview-item.error` 增强为占位 + 底部红条「上传失败」+ hover「重试/移除」，
  顶部加汇总横幅「N 个附件上传失败，发送时将自动跳过」+「全部重试」。

通用规则：占位尺寸与真实缩略图一致（零 CLS）；alt 不再铺在图上、移入占位卡内部独立行；
失败态键盘可达（focusable + Enter 重试）；重试指数退避上限 3 次，超出标记「已失效，需重新上传」。

## 关键约定（本项目）

- 分层铁律：`core`（框架原语）零业务耦合；业务能力一律落 `access/server`，以
  「接口 + 默认实现 + 组合工厂」形式存在。
- 新增可配置项必须**同时**改 `config-schema.ts`（SCHEMA）与 `config-defaults.ts`（DEFAULTS），
  否则漂移守卫测试失败。
- server.ts 是巨型文件（~4700 行），新路由插入需注意位置（IM webhook 必须在 guard 之前）。
- 测试风格：`access/server/test/*.test.cjs`（CommonJS + node:test，require `dist/` 产物，需先 build）。
  集成测试（server.test.cjs / api.integration.test.cjs）会启动子进程，较慢。
