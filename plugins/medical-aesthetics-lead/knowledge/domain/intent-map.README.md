# 意图映射（Intent-map）运营维护指南

本文件（与 `Intent-map.json` 配套）说明运营如何**不写代码**就把用户口语诉求接到知识库项目，
从而提升检索召回。改完 `Intent-map.json` 后跑一次 `node scripts/kb-validate.cjs` 校验、`node scripts/kb-seed.cjs` 重新灌库即可生效。

## 一句话原理

用户说「脸大 / 显老 / 毛孔粗」这类口语，不一定命中项目名或别名。我们把这些口语词写成
**意图映射**：`口语词 → 项目`。检索时只要查询串里**包含**这些词（子串匹配），就把对应项目拉进候选并加权。

例：`"脸大"` 命中意图 `瘦脸脸小 → botox`（`keywords` 含 `"脸大"`），于是把「肉毒素注射」召回，即使项目名里没有"脸大"。

## 一条映射长什么样

```json
{ "intent": "瘦脸脸小", "projectId": "botox", "weight": 3, "keywords": ["脸大", "脸宽", "咬肌", "方脸", "脸胖", "脸小一点"] }
```

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `intent` | 意图名（口语诉求归类，如"面部年轻化""祛斑"） | 同一意图可映射到多个项目 |
| `projectId` | 目标项目 ID，**必须与 `project-catalog.json` 的 `projectId` 完全一致** | 写错会被 `kb-validate` 报错 |
| `weight` | 同意图多项目时的排序权重（1-3，越大越靠前） | 主推项给 3，辅助项给 1-2 |
| `keywords` | 触发召回的口语词数组（子串匹配，含其一即命中） | 越口语越好：脸大/松了/垮/显老 |

## 运营日常怎么加词

1. **发现新口语**：客服/线索里出现高频但没召回的说法（如"脸方""手显老"）。
2. **找对应意图**：看是否已有意图（如"脸型骨相""手部年轻化"）；有则直接往 `keywords` 里加词。
3. **没有意图就新建一条**：复制上面模板，填 `intent`、`projectId`（去 catalog 复制）、`weight`、`keywords`。
4. **校验**：`node scripts/kb-validate.cjs`（报错会告诉你 projectId 拼错或重复）。
5. **生效**：`node scripts/kb-seed.cjs`（清空旧意图表重写）。
6. **回归**：`node scripts/kb-eval.cjs` 看命中率是否提升（新增 query 可直接补进 `golden-queries.json`）。

## 加分技巧

- **同义词穷举**：一个意思多写几个说法（"显老/老了/垮/松了/面部年轻化"）。
- **季节/人群词**：如"秋冬想美白"→补`想变白/提亮`到美白意图。
- **长尾项目**：新增了 catalog 里的长尾项目（瘢痕/妊娠纹/丰唇/私密…），记得同步补一条意图，否则仍然搜不到。
- **避免误召回**：别把太短太通用的词（如单字"纹""脸"）放进去，会干扰其它意图。

## 与 hybrid 语义检索的关系

本项目同时支持**可选语义向量检索**（`MA_EMBED_BASE_URL` 已配时，对查询与项目实时嵌入并叠加余弦相似度）。
意图映射是**零依赖、可解释、即时可控**的第一道召回网；语义向量是补充兜底。两者叠加，召回更全。
即便不接嵌入服务，意图映射也能单独撑起口语召回。
