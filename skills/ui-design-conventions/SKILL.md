# UI 设计与页面开发默认规则

## 核心立场（不可协商）

1. **默认收敛**。不指定风格时，产出的是「看起来本就该是这样」的常规界面，不是有设计感的界面。
2. **不为差异化而差异化**。任何视觉手段（尺寸、颜色、圆角、阴影、渐变、自创图标）都必须先证明它解决了定位、层级或状态问题，否则不用。
3. **实现后必须自查收敛**，见「§8 同屏对比自查」。这是收口步骤，不是可选项。

## 何时加载

- 设计 / 开发 / 改版任何页面、组件、后台、表单、设置页、仪表盘。
- 调整样式、布局、间距、字号、图标、配色。
- 评审或重构现有界面（判断是否过大、过重、过突兀）。
- 用户明确要求「克制 / 收敛 / 常规 / 别太花 / 像产品该有的样子」。

**例外**：用户明确要求营销页、落地页、品牌页、发布会页，或明确要求「突出 / 强调 / 吸睛 / 有视觉冲击」时，放宽 §7 限制，但 §4（图标隐喻）与 §8（自查）仍然有效。

## §1 默认起点：先找同类，再谈设计

动手前先确定界面的**类型**，然后按该类型的行业惯例起步，而不是从空白发挥。

| 界面类型 | 默认气质 | 参照对象 |
|---|---|---|
| 数据后台 / 控制台 | 紧凑、信息优先、低饱和 | Linear、Vercel Dashboard、Grafana |
| 表单 / 设置页 | 清晰分组、单列为主、标签左对齐 | GitHub Settings、Notion Settings |
| 文档 / 阅读 | 大行距、窄栏（680-760px）、高对比正文 | MDN、Stripe Docs |
| 编辑器 / Canvas | 极简 chrome、工具条贴边、内容占满 | Figma、VS Code |
| 对话 / 消息 | 单列、气泡克制、输入区固定 | 主流聊天产品 |
| 移动端 H5 | 单列、大触控区、底部导航 | 系统原生 App |

**没有参照物时宁可更朴素。** 一个平淡但正确的界面，远好过一个有个性但难用的界面。

## §2 尺寸与间距：按五个变量判断，不写死规格

禁止直接套用「统一 8px / 16px / 24px」这类固定规格表，也禁止为了让元素「更清楚」而主动放大。

按顺序评估五个变量，再定具体值：

| # | 变量 | 判断要点 |
|---|---|---|
| 1 | **界面类型** | 后台紧凑、文档宽松、移动单列——见 §1 |
| 2 | **信息密度** | 同屏对象越多，间距越小；表格/列表是高密，详情页是低密 |
| 3 | **平台习惯** | iOS 44pt 触控、Material 48dp、桌面控件 28-36px、桌面密集图标按钮可到 24px |
| 4 | **使用频率** | 高频操作 → 位置更稳定、点击区更大、但视觉更安静；**高频不等于更大更重** |
| 5 | **视觉层级** | 一屏只允许一个主操作；层级靠相对关系，不靠绝对值 |

### 锚点法（推荐，避免拍脑袋）

1. 找到同屏**信息最密**的元素（通常是表格行、列表项、正文段落）。
2. 以它的字号、行高、内边距作为**基准锚点**。
3. 其它元素只允许在锚点上下浮动**一档**（约 2-4px），**最多两档**。
4. 若某元素相对锚点浮出两档以上 → 它已经破坏密度，收敛一档。

### 快速参考区间

完整区间表（分界面类型的字号、行高、控件高度、padding、栅格间距、圆角、阴影）见 `references/spacing-scale.md`。该表是**校准用的量尺**，不是必须遵守的规格——上下文压过表格。

### 硬性上限（工具类界面）

- 同屏字号种类 **≤ 4**。
- 页面标题 **≤ 24px**（工具类）；区块标题 14-16px；正文 13-14px；辅助文字 12px。
- 内容区最大宽度：表格/列表可满宽；表单 560-720px；长文阅读 680-760px。
- 圆角：控件 4-8px，卡片 8-12px，胶囊/标签用 999px 或 4px。**> 16px 需要理由**。

## §3 辅助入口、设置、开关、工具按钮：不抢视觉中心

**判定**：如果第一眼看到界面时，视线先落在设置齿轮、切换开关或某个工具按钮上，而不是落在主内容或主操作上 → 违规。

收敛手段（按优先级）：

1. **靠位置表达**：设置放右上/页面底部，筛选放内容区上方工具栏，批量操作放列表顶部——位置本身就是层级。
2. **降为中性色**：辅助入口默认用次级文字色（非强调色），hover 时才提亮。
3. **hover / focus 才显形**：行内操作（编辑/删除/复制）默认低对比或隐藏，行 hover 时出现。
4. **收进溢出菜单**：≥3 个同类次要操作 → 收进 `⋯` 菜单。
5. **纯图标 + tooltip**：去掉文字标签，只留图标，用 `aria-label` + tooltip 说明。
6. **去掉背景块**：能用描边/纯图标就不用实心色块按钮。

**禁止**：给辅助入口加深色实底、加边框、加大字号、加阴影、加强调色、放进页面正中或做成主按钮同款。

**一屏一主操作**：primary（实心强调色）按钮每屏至多 1 个。其余全部用 secondary / ghost / text 形态。

## §4 图标：必须是一眼可识别的通用隐喻

### 铁律

- **常见功能一律用行业通用隐喻**，不为差异化自创。
- 优先顺序：**项目已在用的图标库 > 成熟开源图标库（Lucide / Heroicons / Material Symbols / Phosphor / Feather）> 系统图标 > 行业通用符号**。
- **同屏同类图标必须同一套**：同一图标库、同一风格（线宽、端点圆角、填充/描边一致）。禁止混用不同库的图标，禁止混用 outline 与 solid。

### 自定义图标的前置检查

自创前先回答：这个功能在 Lucide / Heroicons / Material Symbols / Phosphor / Feather 里有现成图标吗？**有就用现成的。**

确实需要自创时，必须满足：

- 在同一个 24×24 网格内绘制，保留 2px 安全边距，与库图标同一光学尺寸。
- 线宽、端点形状、圆角与所用图标库**完全一致**。
- 轮廓是某个通用符号的**可识别变体**（如「导出」= 通用下载箭头 + 本产品对象轮廓），不是抽象几何。
- 上线前问：不给文字标签，用户 2 秒内能猜对吗？猜不对就补文字或 tooltip。

### 功能 → 通用隐喻映射

完整映射表见 `references/icon-metaphors.md`（约 50 项，含易错对照）。高频几项：

| 功能 | 通用隐喻 | 常见错误 |
|---|---|---|
| 设置 | 齿轮 | 用三点或滑块表示「设置」 |
| 筛选 | 漏斗 | 用齿轮表示筛选 |
| 偏好调节 | 滑块 | 与「设置」混淆 |
| 删除 | 垃圾桶 | 用 × 表示删除（× 语义是关闭/取消） |
| 关闭 / 取消 | × | 用 × 表示删除 |
| 保存 | 软盘 / 下载箭头 | 用星标或心形表示保存 |
| 展开 / 收起 | 尖角 chevron | 与箭头 arrow 混用（chevron 表层级，arrow 表方向） |

### 图标使用细则

- 尺寸与相邻文字对齐：14px 文字配 16px 图标，16px 文字配 20px 图标。
- **光学对齐**：方块类图标（如 `square`、`image`）视觉面积比三角/圆形大，需缩小 1-2px 或减内边距，否则看着比同伴大。
- **纯图标按钮必须有 `aria-label` 和 tooltip**。
- 识别度存疑（> 20% 用户可能猜错）→ **图标 + 文字**，不要为了省空间牺牲识别。

## §5 层级表达：手段有优先级

从最推荐到最不推荐，只有在前一级不够用时才用下一级：

| 优先级 | 手段 | 说明 |
|---|---|---|
| 1 | **位置** | 顶部/左侧=导航，右上=全局操作，底部=危险/终结操作 |
| 2 | **分组与留白** | 靠在一起的自然是一组；组间距 > 组内间距 |
| 3 | **分隔线** | 1px、低对比（边框色），不要用深色粗线 |
| 4 | **轻微颜色** | 次级文字色 / 强调色只用于真正需要指向的地方 |
| 5 | **hover / active / focus** | 交互即反馈，成本最低 |
| 6 | **tooltip / 辅助文字** | 解释而不改变外观 |
| 7 | **状态反馈** | loading / disabled / error / success / empty |
| 8 | **尺寸** | 差异控制在 2-4px，超过就是「放大」 |
| 9 | **色块 / 实底** | 每屏强调色面积建议 < 5% |
| 10 | **边框 / 阴影 / 圆角 / 渐变** | 最后手段，且必须轻量 |

**反直觉但重要**：层级靠**对比**成立，不靠**强度**成立。把次要元素调弱一档，比把主要元素调强一档更有效，也更不容易破坏密度。

## §6 状态必须全覆盖

任何交互元素都要定义这些状态，缺失即为未完成：

`default` / `hover` / `active(pressed)` / `focus-visible` / `disabled` / `loading` / `selected`

任何数据区域都要定义：`loading`（骨架屏或 spinner）/ `empty`（空状态插画 + 一句说明 + 一个主操作）/ `error`（一句人话 + 重试）/ `partial`（部分失败）。

`focus-visible` 用 2px ring 或 outline，**不要 `outline: none` 后不加替代**。

## §7 限用与禁用清单

### 默认不用

- **夸张尺寸**：超过同屏锚点两档以上的字号/间距/控件高度。
- **重色块**：大面积强调色铺底、渐变按钮、彩色卡片背景。
- **大圆角**：> 16px（工具类界面），尤其不要给按钮、输入框、标签用大圆角。
- **厚边框**：> 1px 的常规边框（选中/focus 态的 2px ring 除外）。
- **强阴影**：多层、大扩散半径、彩色阴影。静态容器用 1px 边框，不用阴影；只有真正浮起的层（dropdown / popover / dialog）才用 `0 4px 16px rgba(0,0,0,.12)` 级别。
- **装饰性渐变**：纯装饰的渐变背景、渐变文字、渐变边框。
- **营销页式布局**：巨幅 hero、超粗超大标题、居中巨型 CTA、三段式特性卡——出现在工具类界面即为违规。

### 工程侧

- **不硬编码颜色**：复用项目已有设计令牌 / CSS 变量（如 `--ah-*` 一类），新增令牌需与既有命名体系一致。
- **必须适配深浅两套主题**：跟随系统/宿主主题，两套令牌都给值。
- **对比度**：正文 ≥ 4.5:1，大字/次要文字 ≥ 3:1。
- **响应式**：至少覆盖窄屏（< 640px）与常规桌面；表格窄屏优先横向滚动或卡片化，不要压缩到不可读。
- **动效**：120-200ms，仅 opacity/transform；`prefers-reduced-motion` 下降级为无动画。

## §8 同屏对比自查（收口步骤，必做）

实现完成后、交付前，执行这 6 步：

1. **列清单**：写出同屏已有的元素（表格行、正文、次级按钮、标签、时间戳……）。
2. **定锚点**：挑出信息最密的那一个，记录它的字号、内边距、颜色权重。
3. **逐维对比**：把新元素与锚点在四个维度上比——
   - 字号/尺寸差距 > 2 档？
   - 颜色权重（实底 / 强调色 / 深色）高于锚点？
   - 装饰（边框、阴影、圆角、渐变）多于锚点？
   - 留白明显大于同组其它元素？
4. **回答三个问题**：
   - 第一眼视线会先落在新元素上吗？（应该落在主内容/主操作上）
   - 把新元素删掉，界面会缺功能，还是只是缺装饰？
   - 把它缩小一档、去掉背景、换成中性色，还能认出来吗？（能 → 就该这么做）
5. **收敛**：任一维度超出一档，就降一档后重跑对比。
6. **复核低频元素**：设置、开关、工具按钮单独过一遍 §3「不抢视觉中心」。

完整可勾选清单见 `references/self-check.md`。典型反模式与收敛对照（含代码 before/after）见 `references/anti-patterns.md`。

## §9 交付说明的写法

交付时不要罗列用了什么视觉手法，按这个顺序说：

1. 这个界面的**类型与参照对象**（§1）。
2. 尺寸间距的**判断依据**（五个变量里哪几个起了决定作用）。
3. **主操作是哪一个**，为什么它是唯一的强调点。
4. **辅助入口如何被收敛**（位置 / hover 显形 / 溢出菜单）。
5. **图标来源**（哪个库，自定义了哪几个、为什么）。
6. **自查结果**：与锚点对比后收敛了哪几处。
